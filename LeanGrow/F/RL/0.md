

# RL rambling

- For one successful MCTS training session, gather info as follows. For thms transitioning between clusters, score based on clusters. For thms staying in same cluster (ex. Nat.add_assoc and the like), score based on history of thms. The idea is to separate big transitions (cluster to cluster) from low level proofs (that stay in same cluster, such as Nat.add_assoc) ; actually, it might be good for all transitions between clusters where there are a lot of theorems (as given by 0-th closure)

- For weighting system derived from MCTS variant consider the following aspect. Its important to condition the success on the failure of other approaches. The situation we don't want is one in which one lemma is generally used not that often, be used often in a specific context, which is then ignored by scoring function, because that function isn't conditioned on context.
